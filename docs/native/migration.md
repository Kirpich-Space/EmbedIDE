# План миграции

Этап считается завершённым только после проверок его исходников. Наличие
старого бинарника не заменяет `cargo test`. См. [архитектуру](architecture.md)
и [фактический отчёт сессии](session-report.md).

| Этап | Работа | Критерий перехода |
| --- | --- | --- |
| A — аудит | Сопоставить Electron, Rust, форматы и шаблоны | Карта функций, входной git status, проверка совместимости данных |
| B — архитектура | Закрепить границы модулей и критерии GUI | Ядро не зависит от GUI, явно описаны ограничения |
| C — headless фундамент | Проверить исходники существующего workspace; усилить ошибки и задачи | Build/test/Clippy, коды CLI, JSON и реальные сборки fixtures |
| D — редактор | Проверить Piece Table; добавить line index, file session и Vim state machine | Unicode/model tests, безопасное сохранение, undo grouping, замеры Rope/Piece Table |
| E — GUI | Eframe окно, классические панели, viewport, мышь, вкладки, open/edit/save | Реальная работа с файлами на Linux musl, GUI не блокируется сборкой |
| F — embedded | Потоковая сборка/отмена, diagnostics, LSP, GDB/MI, OpenOCD, UART | Протокольные тесты; аппаратные проверки отдельно с моделью платы и probe |
| G — устойчивость | Профилирование, ограничение истории/логов, большие файлы, упаковка | Измерения на X230/4 GB; Linux/Windows/FreeBSD имеют отдельные результаты |

Выполнены A/B, C и проверяемая часть D: Piece Table, индекс строк,
Vim parser/executor, file session и общий CLI/TUI frontend. Workspace собирается:
132 Rust tests и Clippy проходят. Полноэкранный frontend проверен через 28 PTY
тестов; registry blocker устранён. E/F и полная программа G не выполнены.
Актуальный результат: [fullscreen-editor.md](fullscreen-editor.md).

## Что сохранять при переносе

- Все поля `embedide.json`, включая неизвестные текущему Rust frontend.
- 19 генераторов проектов и их выходные Makefile, linker/startup/memory файлы.
- Каталог 67 MCU, включая origin/size, CPU/FPU, rust target и настройки adapter.
- Существующие пользовательские sources, сборочные manifest и настройки.
- Темы, локализации и offline fonts как входные данные будущего UI, с проверкой лицензий assets.

Legacy `src/core/parseDiagnostics.ts` пригоден как набор входных примеров для
Rust adapter; сопоставление файла по basename нельзя переносить буквально —
при двух `main.c` оно может поставить диагностику не на тот файл.

Генераторы ARM startup/vector и memory layout требуют проверки конкретных плат;
наличие файлов и успешный `open` не означают, что прошивка корректно стартует.
Скрипты установки и Electron packaging остаются только для старого продукта.
Нативная упаковка будет независимой и не должна вызывать существующие release jobs.

## Ближайший следующий шаг

1. Проверить TUI на настоящих терминалах и через SSH; выполнить настроенный CI
   для Windows. FreeBSD остаётся отдельной непроверенной платформой.
2. Согласовать графемные движения/удаление в общем engine с экранным отображением:
   сейчас engine использует Unicode scalar, а TUI отображает графемы.
3. По измерениям длительных сессий доработать memory budget/compaction и обработку
   очень длинных строк; добавить counted Insert и Save As отдельными изменениями.
4. Подключить GUI после отменяемого task runner и платформенных проверок файлового
   слоя. Не переносить terminal viewport/cell coordinates в общее ядро.
